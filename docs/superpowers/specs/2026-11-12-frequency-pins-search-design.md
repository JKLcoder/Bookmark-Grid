# Bookmark Grid：使用频率、置顶与双模式搜索设计

状态：供用户确认；本次只交付设计，不实现功能。

## 目标与已确认范围

帮助用户先找到本插件中最常打开的书签，并在同一个输入框中使用 Chrome 默认搜索引擎。

用户已明确选择：
- 只统计本插件内的点击，不读取浏览历史。
- 全部网格按使用频率排序，同时提供置顶功能。
- 输入框开头增加小型下拉框，切换书签搜索和引擎搜索。
- 每次打开新标签页，默认进入引擎模式。

沿用当前深色紧凑网格、网站小图标、文字/图标统一大小、列数和间距设置、自定义名称、原生链接导航以及书签变化同步。不增加后端、账号、云同步、文件夹导航或第三方推荐。

## 考虑过的方向

1. 顶部单独展示常用区、其余继续按名称排序：位置稳定，但重复占用页面空间；用户没有选择。
2. 全网格按使用频率排序并允许置顶，共用输入框切换搜索模式：用户选择的方向，充分利用现有网格。
3. 两个独立搜索框：功能边界直观，但占用更多空间；用户选择共用输入框。

## 供确认的具体行为

以下细节为本次设计建议，尚不视为用户已逐项批准。

### 频率排序与置顶

- 先显示置顶书签，再显示其余书签；保持同一个连续网格，不增加分组卡片。
- 两部分内部使用相同规则：累计打开次数降序 → 最近打开时间降序 → 现有中文友好的名称排序 → 书签 ID 确定性兜底。
- 未使用过的书签计数为 0；没有历史数据时自然退回名称排序，不补算升级前的次数。
- 每个 Item 悬停或键盘聚焦时，在现有编辑按钮旁显示置顶/取消置顶操作；触屏操作按钮可见。置顶后保留小型固定标记。
- 置顶操作只改变插件本地状态，不移动、修改或删除 Chrome 原始书签。重复 URL 仍按不同书签 ID 分别统计和置顶。
- 为避免操作目标突然移动，点击产生的频率变化在下次打开或刷新页面时影响排序；置顶/取消置顶立即生效。搜索结果仍按同一套置顶与频率规则呈现。

### 点击统计边界

- 统计左键、键盘激活，以及 Ctrl/Command/Shift 修饰点击和中键打开；每次打开操作只计一次。
- 统计的是插件内“发起打开”的操作次数，不代表网页成功加载、访问时长或浏览器全部使用行为。
- 右键菜单本身不计数；通过浏览器右键菜单选择打开链接无法仅凭当前页面事件准确识别，因此不承诺覆盖。
- 必须保留原生 anchor 行为；记录失败不得阻止打开链接，也不得导致重复打开。
- 统计写入由后台协调，避免多个新标签页并发覆盖计数；当前标签页导航离开时也应尽力完成已交给后台的写入，不承诺在浏览器被强制终止时绝对不丢失尚未完成的记录。

### 共用输入框

- 输入框左侧为紧凑下拉框：`引擎` / `书签`。
- 每次新开或刷新页面均默认 `引擎`，不记住上一次的模式。
- 引擎模式：输入只保留关键词，不过滤网格、不联网提供联想；非空内容按 Enter 后，通过 `chrome.search.query` 调用 Chrome 配置的默认搜索引擎，在当前标签页显示结果。空白输入不提交，中文输入法组词时 Enter 不触发搜索。
- 书签模式：输入实时过滤自定义名称、原始标题、URL、域名和文件夹路径，不向搜索引擎发送内容；Enter 不自动跳转或打开第一个结果。
- 切换模式保留已输入文字，切换到书签模式立即用该文字过滤；切回引擎模式恢复全部网格。
- 清空输入恢复完整网格；占位文案随模式改变。书签链接仍按用户原生点击手势打开。
- Chrome 搜索 API 不可用或执行失败时显示可重试提示，不擅自改用固定搜索站点。

## 数据与权限

- 继续以 Chrome Bookmarks API 为原始书签的唯一数据源，不复制书签树到持久化存储。
- 别名 `name:<id>`、布局 `layout:*` 保持兼容；新增独立的统计和置顶记录，均按 bookmark ID 关联并存入 `chrome.storage.local`。
- 删除书签或整个目录时，清理相关别名、统计和置顶记录；页面加载时可补充清理遗留数据。
- 必要权限：现有 `bookmarks`、`storage`、`favicon` 加上 `search`。不新增 `history`、`tabs`、`host_permissions`，不修改浏览器默认搜索引擎。
- 书签数据、使用记录和置顶状态不上传。仅当用户在引擎模式主动提交时，关键词交给其默认搜索引擎；设置/说明需准确反映这一边界。

## 后续实现的验收重点

- 置顶优先、频次及最近时间排序、同频率名称兜底、全新数据和删除清理。
- 多标签页连续/并发记录不覆盖；左键和中键不重复计数；编辑/置顶/右键菜单不误计数；导航不受统计失败影响。
- 默认引擎模式；模式切换保留文字且不误发搜索；空白与输入法组词不提交。
- 引擎模式使用 Chrome 默认引擎；书签模式各字段过滤保持正确；API 失败可重试。
- 旧别名、布局和统一字号继续可用；窄屏、键盘焦点、触屏和原生新标签页手势正常。
