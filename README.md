# Bookmark-Grid
Chrome Plugin

轻量的 Chrome Manifest V3 新标签页扩展。将所有层级的书签扁平化为文字网格，支持本地自定义名称、实时搜索与书签变化同步。

## 开发与构建

需要 Node.js **22.12+**（本云环境使用 24.22.1）和 npm。

```bash
npm ci
npm test
npm run build
```

构建结果为 `dist/`，包括 Manifest、React 页面、静态资源和后台清理脚本。所有资源打包在本地，无 CDN、后端或账号。书签筛选和使用记录在本地处理；仅在引擎模式主动提交时，将关键词交给设置中选择的搜索引擎。

`npm run dev` 可用于页面开发，但普通网页没有 Chrome Bookmarks API，会显示加载扩展的提示，不会伪造书签。验证真实行为请加载 `dist/`。修改后重新构建，在扩展页点击重新加载，并打开新标签页。

## 在 Chrome 安装

也可直接下载仓库中的 [已构建扩展 ZIP](downloads/bookmark-grid-dist.zip)（在 GitHub 文件页点击 Download raw file），解压后按下面第 2–5 步加载解压出的 `dist/`，无需安装 Node.js。ZIP 对应本次提交的构建版本，修改源码后需要重新构建。

1. 运行 `npm ci` 和 `npm run build`。
2. 在 Chrome 地址栏打开 `chrome://extensions`。
3. 打开右上角“开发者模式”。
4. 点击“加载已解压的扩展程序”，选择本项目的 **dist 目录**，不是项目根目录。
5. 新建标签页；如 Chrome 提示新标签页变更，请保留此扩展。

已有其他新标签页扩展时，请先停用它们以免覆盖冲突。书签功能可离线使用；网页搜索和访问网站需要网络。安装不需要账号或 API 密钥。

## 使用

界面采用深色紧凑布局，每个 Item 在名称前显示与文字等大的小号网站图标，不展示域名或 URL。URL、域名和原路径仍可搜索；真实链接地址及原生点击行为保持不变。默认 6 列、行间距 4px、列间距 12px，文字与图标同为 16px。

- 自动读取全部书签，包括多层嵌套目录；保留重复 URL，不显示文件夹分组。
- 置顶书签优先，然后按累计打开次数、最近打开时间排序；相同时按中文友好的显示名称排序。全新安装尚无点击记录时按名称排序。
- 输入框左侧下拉切换“引擎 / 书签”，每次打开或刷新默认进入引擎模式。引擎模式不筛选书签，按 Enter 使用设置中选择的搜索引擎，在当前标签页打开结果；输入过程不发送关键词，不提供在线联想。书签模式实时筛选自定义名称、原标题、URL、域名和原文件夹路径，Enter 不提交网页搜索。切换模式保留文字，清空恢复全部。
- 点击书签按设置在当前或新标签页打开（默认当前标签页）；Ctrl / Command 点击、中键点击仍由原生链接处理。新标签页不保留 opener。
- 悬停或 Tab 聚焦 Item 出现编辑和置顶按钮，触屏上按钮始终可见。
- 编辑仅改变显示名称；留空或点击“恢复原标题”删除该别名。无别名时原标题变化会立即反映。
- 设置入口支持列数（自动或 1–12 列）、行间距（0–32px）、列间距（0–48px）、文字与图标的统一大小（12–28px），调整即时预览并保存在本机，可一键恢复默认。窄屏会自动减少实际列数，避免横向溢出。

## 搜索与打开偏好

设置中可选择默认搜索引擎：百度、Google，或“跟随 Chrome”（兼容旧版本的默认值）。百度使用 `https://www.baidu.com/s?wd=...`，Google 使用 `https://www.google.com/search?q=...`；中文和特殊符号均进行 URL 编码。输入时不请求搜索引擎，仅主动提交时导航。该设置只影响插件内搜索，不修改 Chrome 自身配置。

“网站打开方式”提供当前标签页和新标签页，控制书签点击，默认当前标签页。搜索结果始终在当前标签页打开。原生 Ctrl/Command/Shift 点击与中键行为保留。两项偏好仅保存在本机，刷新后保留；恢复默认会一并恢复为“跟随 Chrome”和“当前标签页”。无需新增权限。

## 使用频率与置顶

- 只记录从本插件左键、键盘激活、Ctrl/Command/Shift 点击及中键发起的打开操作，不读取浏览器历史，也不记录其他入口的访问。次数不代表网页加载成功或访问时长。
- 升级前的使用次数无法补算，新版启用后从 0 开始累计；重复 URL 按不同书签 ID 独立记录。
- 悬停或键盘聚焦时点击图钉可置顶/取消置顶，已置顶书签保留图钉标记；所有书签仍在同一个网格中。
- 置顶立即改变排序；点击次数变化在下次新开或刷新页面后影响排序，避免当前页面的目标突然移动。
- 右键菜单本身不计数；通过浏览器右键菜单选择打开链接不在可靠统计范围内。
- 后台队列协调多标签页写入，统计失败不阻止原生打开。浏览器强制关闭前尚未完成的写入仍可能丢失。
- 本地 `usage:<id>` 保存 `{ count, lastOpened, pinned }`，不上传、不含完整书签树；删除书签/目录会清理记录。

## 数据与权限

网站小图标通过 Chrome 自带的 `/_favicon/` 接口读取，需要 `favicon` 权限和 Chrome 93+。不使用 Google S2 或其他远程图标服务，不会把书签 URL 发给第三方图标服务。无可用图标、加载失败或非 HTTP(S) 书签使用随扩展打包的通用图标。文字与图标严格使用相同的 CSS 像素尺寸；旧版本没有此设置时自动使用 16px。

申请 `bookmarks`、`storage`、`favicon`、`search`，没有 `history`、`tabs` 或 `host_permissions`。选择“跟随 Chrome”时通过 `chrome.search.query` 使用浏览器默认搜索引擎；选择百度或 Google 时，明确提交后导航到所选引擎的搜索结果地址，不修改 Chrome 默认引擎；书签读取使用 `chrome.bookmarks.getTree()` / `get()` 并监听 `onCreated`、`onChanged`、`onMoved`、`onRemoved`，不修改、重命名或删除原始书签。

布局偏好独立使用 `layout:columns`、`layout:rowGap`、`layout:columnGap`、`layout:itemSize`、`layout:searchEngine`、`layout:openInNewTab` 保存；不会与 `name:` 别名键混淆。原始书签是唯一数据源，不复制到持久化存储。自定义名称存入 `chrome.storage.local`，每个书签单独保存为 `name:<bookmarkId>` → 名称，内存中再合并为 ID 到别名的映射。独立键避免多页面编辑不同书签时覆盖整个别名表。多个页面修改同一 ID 时以后一次写入为准。

后台 service worker 在删除书签/整个目录时清理对应别名、使用统计和置顶记录，即使新标签页没有打开也会运行。页面加载时再次清理遗留记录。存储或读取失败会提示错误和重试，不报告虚假成功。其他扩展页面的 storage 变化也会触发刷新。

## 项目结构

```text
public/
  manifest.json          MV3 新标签页与最小权限
  background.js          消息处理与删除事件清理
  usage-store.js         串行使用次数/置顶存储
src/
  bookmarks.ts           递归扁平化、搜索、拼音排序、名称清理
  api.ts                 真实 Chrome API 和本地存储适配
  usage.ts / ranking.ts   后台消息与置顶/频率排序
  SearchBar.tsx           共用输入框与模式切换
  engine-search.ts       默认引擎搜索 API
  App.tsx                网格、搜索、编辑对话框、设置说明
  main.tsx               React 入口
  style.css              响应式布局、键盘焦点、触屏适配
tests/                   数据、API、后台与 React 交互测试
scripts/smoke.mjs        真实 Chromium 解压扩展冒烟测试
dist/                    npm run build 生成，可直接加载
```

## 自动化测试

`npm test` 使用模拟书签树及 Chrome API，覆盖单层/多层/空目录/重复 URL、名称保存恢复、原标题变化、各字段搜索、删除清理、中文排序、空状态，以及错误处理、事件订阅释放和编辑交互。

真实浏览器验证：

```bash
npm run build
npm run test:e2e
```

默认使用 `/usr/lib/chromium/chromium`（直接执行浏览器，避免系统启动包装脚本重写扩展参数）。其他位置可设置 `CHROMIUM_PATH=/path/to/chromium npm run test:e2e`。需要支持加载解压扩展的 Chromium；不需要修改浏览器默认用户配置。测试创建并最终删除独立的临时浏览器配置和测试书签，不操作个人浏览器。覆盖真实 API 读取、多层搜索、别名持久化、原标题保护、实时事件、Escape 关闭对话框、390px 窄屏、无外部页面请求、页面关闭后清理别名和空书签状态。截图输出到 `/tmp/bookmark-grid-desktop.png` 与 `/tmp/bookmark-grid-mobile.png`。

在受管理的云浏览器中，如果扩展参数被忽略或企业策略禁止书签编辑，`test:e2e` 可能无法启动其临时扩展/创建测试书签。不要修改系统企业策略。可运行 `npm run test:browser`：它对生产构建页面注入模拟 Chrome API，验证实际 Chromium 中的搜索、改名、重载持久化、对话框和响应式布局。此检查不能替代真实扩展 API 验证。

本次云环境验证结果：95 项单元/集成测试通过；TypeScript 与 Vite 构建通过；生产页面浏览器测试通过。真实解压扩展测试因受管理 Chromium 未加载命令行指定的扩展而超时，未完成；环境还设置了 `EditBookmarksEnabled: false`。在个人 Chrome 中请按上述步骤加载 `dist/` 完成最终安装验收。

## 1.5 界面优化

沿用已确认的紧凑原型：压缩顶部留白，保留纯名称网格；搜索按钮和当前搜索引擎始终可见，按 `/` 快速定位搜索框。置顶与编辑按钮在悬停或键盘聚焦时显示，触屏始终显示。

设置中的列数是期望列数，实际列数随窗口宽度和字号调整，面板会显示当前列数。文字和图标保持同样大小；较大字号和触屏会减少列数以保护名称可读性。布局与搜索/打开设置分别恢复默认。

偏好设置即时预览并自动保存。页面显示保存状态；失败提示在关闭设置后仍保留，可重试或撤销未保存的偏好改动。设置面板支持 Escape、Tab 边界和点击外部退出。不改变已有偏好键、别名、置顶和使用频率数据，也不新增权限或依赖。
